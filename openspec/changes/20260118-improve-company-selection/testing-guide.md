# Testing Guide: 業務員公司選擇 UX 改進

**測試日期**: 待測試
**測試環境**: 本地開發環境

---

## 🚀 啟動測試環境

### 1. 啟動 Backend
```bash
cd my_profile_laravel
docker-compose up -d
docker exec -it my_profile_laravel_app php artisan migrate:fresh --seed
```

驗證: http://localhost:8080/api/health

### 2. 啟動 Frontend
```bash
cd frontend
npm run dev
```

訪問: http://localhost:3001

### 3. 登入測試帳號

使用 Seeder 建立的業務員帳號：
- Email: `salesperson@example.com`
- Password: `password`

## ✅ 測試案例

### Test Case 1: 公司搜尋功能

**步驟**:
1. 登入業務員帳號
2. 進入 Dashboard → 公司資訊區塊
3. 點擊「編輯」按鈕
4. 確保「我是自營業者」未勾選
5. 點擊「搜尋公司名稱或統一編號」按鈕

**測試項目**:
- [ ] Combobox 開啟（Dialog 顯示）
- [ ] 輸入框 placeholder 正確顯示
- [ ] 搜尋圖示顯示

**測試 1.1: 搜尋公司名稱**
1. 輸入「台灣」
2. 等待 300ms
3. 觀察搜尋結果

**預期**:
- [ ] 顯示 Loading 狀態
- [ ] 搜尋結果出現（如有）
- [ ] 最多顯示 10 筆
- [ ] 每筆顯示「公司名稱」和「統編」
- [ ] 滑鼠懸停時高亮

**測試 1.2: 搜尋統編**
1. 清空輸入框
2. 輸入「12345678」
3. 等待 300ms

**預期**:
- [ ] 精確匹配該統編的公司

**測試 1.3: 搜尋無結果**
1. 輸入「絕對不存在的公司名稱 XYZ123」
2. 等待搜尋完成

**預期**:
- [ ] 顯示「找不到相符的公司」
- [ ] 顯示「新增公司」按鈕

**測試 1.4: 選擇公司**
1. 搜尋「台灣」
2. 點擊其中一筆結果

**預期**:
- [ ] Combobox 關閉
- [ ] 選中的公司顯示在表單下方
- [ ] 顯示公司名稱和統編
- [ ] 顯示「清除」按鈕

**測試 1.5: 清除選擇**
1. 點擊「清除」按鈕

**預期**:
- [ ] 選中的公司被清除
- [ ] 可以重新選擇

### Test Case 2: 新增公司功能

**測試 2.1: 從搜尋無結果新增**
1. 搜尋「新公司測試 ABC」
2. 點擊「新增公司」按鈕

**預期**:
- [ ] Combobox 關閉
- [ ] 新增公司 Dialog 開啟
- [ ] 顯示表單欄位（公司名稱、統編）

**測試 2.2: 表單驗證**
1. 不填任何欄位，直接點擊「確認新增」

**預期**:
- [ ] 顯示「公司名稱為必填」錯誤

2. 填寫公司名稱「測試公司」
3. 統編填寫「123」（不足 8 位）
4. 點擊「確認新增」

**預期**:
- [ ] 顯示「統一編號必須為 8 位數字」錯誤

**測試 2.3: 成功新增**
1. 公司名稱：「測試科技股份有限公司」
2. 統編：「12345678」
3. 點擊「確認新增」

**預期**:
- [ ] 顯示 Loading 狀態（按鈕）
- [ ] 成功後顯示 Toast 提示「公司新增成功」
- [ ] Dialog 關閉
- [ ] 新建的公司自動被選中
- [ ] 顯示在表單下方

**測試 2.4: 統編選填**
1. 點擊「搜尋公司」
2. 搜尋無結果
3. 點擊「新增公司」
4. 公司名稱：「無統編測試公司」
5. 統編：留空
6. 點擊「確認新增」

**預期**:
- [ ] 成功新增
- [ ] 公司資訊顯示「無統編」

**測試 2.5: 重複新增**
1. 嘗試新增已存在的公司（名稱+統編重複）

**預期**:
- [ ] 顯示錯誤訊息「此公司已存在，請使用搜尋功能」

### Test Case 3: 自營業者功能

**測試 3.1: 切換到自營業者**

2. 點擊「儲存公司資訊」

### Test Case 4: 切換確認對話框

**測試 4.1: 公司 → 自營**
1. 先選擇一家公司（例如「台灣科技」）
2. 勾選「我是自營業者」

**預期**:
- [ ] 顯示 Alert Dialog
- [ ] 標題：「⚠️ 確認切換為自營業者？」
- [ ] 內容：「切換後，您先前選擇的公司資訊將被清除。」
- [ ] 兩個按鈕：「取消」、「確認切換」

3. 點擊「取消」

**預期**:
- [ ] Dialog 關閉
- [ ] 保持原本的公司選擇
- [ ] Checkbox 恢復未勾選

4. 再次勾選，點擊「確認切換」

**預期**:
- [ ] Dialog 關閉
- [ ] 公司選擇被清除
- [ ] 顯示營業名稱輸入框

**測試 4.2: 自營 → 公司**
1. 先填寫營業名稱「測試工作室」
2. 取消勾選「我是自營業者」

**預期**:
- [ ] 顯示 Alert Dialog
- [ ] 標題：「確認切換為公司業務員？」
- [ ] 內容：「切換後，您的自營業者名稱將被清除。」

3. 點擊「確認切換」

**預期**:
- [ ] 營業名稱被清除
- [ ] 顯示公司搜尋 Combobox

### Test Case 6: 無障礙性測試

**測試 6.1: 鍵盤導航**
1. 使用 Tab 鍵在表單間移動

**預期**:
- [ ] 所有可互動元素都能 Focus
- [ ] Focus 順序合理
- [ ] Focus 狀態清楚可見（藍色外框）

2. 開啟 Combobox，使用鍵盤操作
- Tab: 移動到輸入框
- 輸入文字: 觸發搜尋
- Arrow Down/Up: 在結果間移動
- Enter: 選擇項目
- Esc: 關閉 Combobox

**預期**:
- [ ] 所有鍵盤操作正常
- [ ] 選中項目有高亮

**測試 6.2: Screen Reader（可選）**
使用 VoiceOver (Mac) 或 NVDA (Windows) 測試

**預期**:
- [ ] 所有元素都被正確讀取
- [ ] ARIA labels 正確
- [ ] 錯誤訊息即時宣告

**測試 6.3: 色彩對比**
使用 Chrome DevTools Accessibility 檢查

**預期**:
- [ ] 所有文字色彩對比 >= 4.5:1
- [ ] 錯誤訊息色彩對比 >= 4.5:1
